## tabview 滑动真根因（SNAPPABLE）+ 用户确认配置1 + 工程重新输出

- 诊断链：EEZ 版注入真实拖动（SendInput）→ 97 次 PRESSING/0 次 SCROLL（断点在输入链）；
  纯 LVGL 对照版正常滚；探针实测内容区 scroll_right=480、page chain_h=1、snap_x=CENTER
  （离屏页 lv_obj_get_width=0 是惰性布局假象，update_layout 后 480x320）。
- ★ 真根因：内容区 SNAP_CENTER 吸附滚动模式下，内核 find_scroll_obj 不按普通溢出，
  走 has_more_snap_points()（lv_indev_scroll.c:353-360）数带 SNAPPABLE 的子对象当吸附点；
  旧版 Tab 页被裁掉 SNAPPABLE（watch 裁法）→ 零吸附点 → 内容区被判不可滚 → 拖动全废。
  eez-test 实测可滑形态 = Tabview 与 Tab 都只裁 SCROLLABLE（产物仅一条
  lv_obj_remove_flag(obj, LV_OBJ_FLAG_SCROLLABLE)）。
- 用户确认：EEZ 控件面板 Tabview + Tab 两控件，Tabview 里必须放 Tab（手册配置 1，
  "Place Tab widgets immediately under TabView"，asar 内置文档挖证）。
- 工程已按此重新输出：build_example.py flags 修正（Tab/Tabview 只裁 SCROLLABLE、
  label 留链）→ CLI 构建 ok → 产物 flags 终检通过 → 仿真器 7/7 编译链接 0 错。
- 教训沉淀：EEZ widgetFlags 是最终态白名单；"拖不动/滚不动"三查——① remove_flag 是否
  误伤 SCROLLABLE/SNAPPABLE/SCROLL_CHAIN_*，② snap 模式下子对象 SNAPPABLE，
  ③ 离屏对象尺寸要用 update_layout 后再读。自动拖动注入（SendInput+FindWindow/
  MainWindowHandle+SW_RESTORE）曾因窗口被用户关闭/最小化屡次失手，鼠标控制权须让给用户。
